You are building a small interactive web app (React + TypeScript + Vite) called “Intelligence Is Overrated? — Life Sim”. It simulates lives as a series of life-event cards with D&D-style d20 checks with Income as the main metric that we score lives on. It also computes luck as two components: (1) Opportunity luck (quality of the hand of events drawn vs deck expectation) and (2) Roll/Resolution luck (did the agent outperform their own expected EV given their traits and the events drawn). Show both separately and also show “Net luck = opportunity + roll” (we’ll evaluate if it’s useful).

Core requirements:
1) Single Life mode:
   - User can either (a) generate random traits or (b) manually input trait scores.
   - Traits: INT, WORK, SOC, CHAR, RISK. Score range 0–20 (accept 0–20; if user enters outside, clamp).
   - Modifiers: mod = floor((score - 10)/2).
   - World mode dropdown: normal | nepo | meritocracy (affects how trait mods contribute to checks; do not create separate decks).
   - Toggle: “Same deck for everyone” (when ON, use a deterministic stage-by-stage event draw sequence based only on seed+stage, not agent traits; when OFF, draw independently per agent using the RNG).
   - Seed input (string or number). Seed must make runs reproducible and shareable (e.g., include seed and settings in URL query params).
   - Run the simulation and render a timeline (Stage 1..8) with:
     - Event name
     - Risk gate outcome (if applicable): gate roll + gate mod + DC
     - Main roll: roll + total mod + DC
     - Success/Fail
     - jump_pct and growth_delta applied
     - Income after stage
   - Show final income, and show luck:
     - Opportunity luck (EV units)
     - Roll luck (EV units)
     - Net luck (sum)
   - Also show EV summaries:
     - EV_baseline_hand (deck expected intrinsic EV)
     - EV_hand (this hand’s intrinsic EV)
     - EV_expected (agent expected EV given traits/world)
     - EV_realized (realized EV)
     - Verify identity in UI: EV_realized - EV_baseline_hand ≈ (opp_luck + trait_advantage + roll_luck)
       where trait_advantage = EV_expected - EV_hand.
     - (Allow tiny floating rounding differences.)

2) Mass Simulation mode:
   - User chooses N agents (default 10,000; options: 1k / 10k / 50k).
   - User chooses world mode and same-deck toggle and seed.
   - Generate agents with random traits using: 3d6 + 2 (clamp 0..20) per trait (fast and bell-ish).
   - Simulate each agent’s life, compute final income and luck components.
   - Show top 10 and bottom 10 agents by final income:
     - Traits
     - Final income
     - Opportunity luck, Roll luck, Net luck
     - Brief event list (names + success/fail)
   - Also show quick aggregate charts:
     - Histogram of final income (simple binning)
     - Scatter plots: all the traits and luck outcomes vs final income, so we can see what trait was most important (simple SVG plot is fine; no need for heavy libs)

Simulation model:
- 8 stages total.
- Stage 1 is special Education card: “Where You Land After High School” – everyone gets it at stage 1. It is NOT drawn from the deck.
  - Education roll: d20 + [INT_mod*1.0 + WORK_mod*0.5 + SOC_mod*1.0] with world multipliers applied the same way as other checks.
  - Threshold ladder to determine outcome (configure in config.json):
    - Elite institution: growth_delta_success = +0.020
    - Strong university: +0.010
    - Regional/state: +0.006
    - Community/vocational: +0.003
    - Straight to workforce: +0.000
  - Education should apply immediately at Stage 1 as a growth_delta, then proceed to also draw a regular event for Stage 1 OR not? Choose: Stage 1 is education only (simpler). Then stages 2..8 draw 7 events. Total 8 “moments”: 1 education + 7 events.
- For drawn event stages (2..8): each stage draws 1 event card from events.json.
- Income model:
  - start income = 40,000
  - start growth = 0.03
  - each stage:
    - apply event effects to temporary jump_pct and persistent growth
    - income *= (1 + growth)
    - income *= (1 + jump_pct)  // jump_pct resets to 0 after applying
  - clamp growth to a reasonable range, e.g. [-0.05 .. +0.30] to avoid absurdity
  - clamp income floor at e.g. 1,000 to avoid negative/infinite weirdness

Event resolution:
- Each event has:
  - DC
  - check_traits weights (small weights, typically 1.0 and 0.5)
  - optional risk gate: risk_gated, risk_gate_DC, risk_gate_weight (usually 1.0)
  - success effects: jump_pct_success and growth_delta_success
  - fail effects: jump_pct_fail and growth_delta_fail
  - “gate_fail” behavior: treat as a neutral no-effect outcome (jump 0, growth 0) — do NOT apply the event’s fail penalties when gate fails. This is important.

World mode:
- Implement as multiplicative scaling on trait mods during checks:
  total_mod += mod(agent[trait]) * worldMultiplier[trait] * eventWeight[trait]
- World multipliers are in worldModes.json.

Precomputed EV tables (non-arbitrary):
- Precompute EV_success[stage] and EV_fail[stage] for each event, independent of agent income, using:
  - normalized income = 1.0
  - base growth = config.baseGrowthEV (same as 0.03)
  - horizon: stages 2..8 for events (7 stages). But stage index can still be 1..8; just compute for 1..8 and use the relevant ones.
- For an event at stage t, remaining = (8 - t + 1) stages INCLUDING that stage’s income application. Use the formula:
  baseline_total = sum_{i=0..remaining-1} (1+g0)^i
  with_success_total = sum_{i=0..remaining-1} (1+jump_success)*(1+g0+growth_delta_success)^i
  with_fail_total = sum_{i=0..remaining-1} (1+jump_fail)*(1+g0+growth_delta_fail)^i
  EV_success[t] = with_success_total - baseline_total
  EV_fail[t] = with_fail_total - baseline_total
- For gate_fail, realized EV should be 0 (neutral) at that stage.

Luck calculations:
Define:
- intrinsic_expected_EV(event, stage): trait-independent expected EV using a reference person with total_mod=0.
  - p_gate = P(d20 + 0 >= risk_gate_DC) if risk_gated else 1
  - p_main = P(d20 + 0 >= DC) if roll_required else 1
  - return p_gate * (p_main*EV_success[stage] + (1-p_main)*EV_fail[stage])
- EV_baseline_hand: sum over stages (2..8) of weighted_mean_over_deck(intrinsic_expected_EV(event,stage), drawWeight(event)).
- EV_hand: sum over stages of intrinsic_expected_EV(drawn_event,stage).
- agent_expected_EV(event,stage): uses agent mods and world multipliers and event weights to compute p_gate and p_main (still exact, not Monte Carlo), and returns p_gate*(p_main*EV_success + (1-p_main)*EV_fail).
- EV_expected: sum(agent_expected_EV over drawn events).
- EV_realized: sum over events of realized EV (EV_success if succeeded, EV_fail if failed, and 0 if gate_fail).
Then:
- opportunity_luck = EV_hand - EV_baseline_hand
- roll_luck = EV_realized - EV_expected
- net_luck = opportunity_luck + roll_luck
- trait_advantage = EV_expected - EV_hand (display separately, not labeled luck)

Probability helper:
- P(d20 + bonus >= DC):
  needed = DC - bonus
  if needed <= 1 => 1.0
  if needed >= 21 => 0.0
  else => (21 - needed)/20

Deck draw:
- Use rarity weights: common=5, uncommon=3, rare=1, jackpot=0.3, sinkhole=0.7
- When same-deck toggle is ON in mass sim, the deck draw sequence per stage should be identical for all agents:
  - Use RNG seeded with (seed + "|stage" + stageNumber) and draw one event for that stage
  - Use the same drawn event for every agent at that stage
- When same-deck toggle is OFF, each agent draws independently using RNG seeded by (seed + "|agent" + index)

UI/UX:
- Two tabs: Single Life / Mass Simulation
- In Single Life, show timeline cards and an income line chart (simple SVG is fine).
- In Single Life, the user should be able to input the trait scores for the agent or click a button to have them randomly assigned. They should also be able to input the agent's name
- In Mass, let's find some library or file of first names and last names, and generate a random name for each agent
- In Mass, show top/bottom 10 in tables and a histogram chart.
- Keep it fast, clean, and readable.
